## 引子

做 AI Agent 开发，第一个遇到的难题往往不是"怎么让 Agent 更聪明"，而是**"怎么让 Agent 记住该记的东西"**。

全塞进去？上下文窗口直接爆炸。
只留最近几条？历史关键信息全丢了。
用向量库检索？系统复杂度陡增，嵌入模型质量直接决定效果。
做知识图谱？维护成本高到劝退。

这不是选择题，是**工程权衡题**。

---

## 一、AI Agent 的 8 种记忆策略

我们先把所有选项摆到桌面上，看看每种策略的本质是什么。

| # | 策略 | 核心机制 | 一句话类比 |
|---|------|---------|-----------|
| 1 | **全量记忆** | 保留所有历史对话 | 录音笔——什么都记 |
| 2 | **滑动窗口** | 只保留最近 N 轮对话 | 黑板擦——旧的擦掉 |
| 3 | **相关性过滤** | 按关键词/语义筛选保留 | 荧光笔——划重点 |
| 4 | **摘要/压缩** | 定期总结历史对话要点 | 会议纪要——提炼精华 |
| 5 | **向量数据库（RAG）** | 语义检索历史记忆 | 图书馆索引——按需查找 |
| 6 | **知识图谱** | 结构化实体关系存储 | 思维导图——关系网络 |
| 7 | **分层记忆** | 工作记忆 + 长期记忆分层 | 大脑记忆系统——短期缓存+长期存储 |
| 8 | **类 OS 内存管理** | 模拟操作系统的换入换出 | 虚拟内存——按需加载 |

每种策略都有其**适用边界**，没有银弹。

## 二、选型决策框架（四步法）

选记忆策略，先对齐三点：**场景目标、成本预算、技术复杂度**。

### Step 1: 看对话时长与记忆跨度

| 类型 | 特征 | 典型场景 |
|------|------|---------|
| 短对话 | ≤5 轮 | 一次性问答、简单 QA |
| 长时对话 | ≥20 轮 | 任务型 Agent、多步推理 |
| 跨天记忆 | 多天/多会话 | 个人助理、陪伴型 Agent |

### Step 2: 评估关键需求

问自己四个问题：

1. **是否要精准事实回溯？** → 需要强一致性，排除纯摘要方案
2. **是否需语义联想？** → 需要向量检索或知识图谱
3. **是否对成本敏感？** → 全量记忆和 RAG 都有额外 LLM 调用开销
4. **是否有隐私合规要求？** → 需要区分临时缓存和持久化存储

### Step 3: 技术与运维能力

| 能力项 | 低 | 中 | 高 |
|--------|---|---|---|
| 向量库运维 | 用托管服务 | 自建 Milvus/Chroma | 分布式集群调优 |
| RAG 工程经验 | 无 | 做过 demo | 生产级部署 |
| LLM 调用开销接受度 | 不接受 | 可接受摘要/压缩 | 可接受多轮检索 |
| 知识图谱构建 | 无经验 | 有 Neo4j 经验 | 有自动抽取管线 |

### Step 4: 合规与数据治理

- 用户数据是否需加密、可删除？（GDPR/个人信息保护法）
- 是否要区分"工作记忆"（临时）与"长期记忆"（持久化）？
- 是否有数据留存期限要求？

## 三、策略选型速查表

| 策略 | 适用场景 | 优点 | 风险/成本 |
|------|---------|------|----------|
| 全量记忆 | 极短对话、简单 QA | 实现最简单 | **上下文爆炸**、成本高 |
| 滑动窗口 | 成本敏感、短时对话 | 开销低、实现简单 | 易丢失历史信息 |
| 相关性过滤 | 信息密集型对话 | 保留关键知识 | 重要性评估难、需调参 |
| 摘要/压缩 | 长对话需保留要点 | **大幅节省上下文** | 可能丢失细节/事实 |
| 向量数据库（RAG） | 需长期记忆、语义检索 | 语义检索高效、可扩展 | 依赖嵌入模型质量、系统复杂度高 |
| 知识图谱 | 知识密集型应用（客服/科研） | **支持复杂推理** | 维护成本高、构建慢 |
| 分层记忆 | 复杂任务型 Agent | 兼顾短期灵活与长期可靠 | 多模块协同、调优成本高 |
| 类 OS 内存管理 | 低延迟长时任务 | 结构清晰、可"无限"扩展 | 需模拟换入换出逻辑、工程复杂 |

## 四、典型组合建议（实战）

单一策略往往不够，**组合使用**才是生产级方案。

### 场景 1: 客服机器人

**推荐**：向量数据库（RAG）+ 知识图谱

- 向量库做**快速语义检索**（用户问"怎么退款"，召回相关流程）
- 知识图谱存储**产品/流程结构化知识**（退款政策的条件、时效、例外情况）
- 支持**复杂问题拆解**（"我买了 A 产品用了 3 天能退吗" → 查询图谱中的政策规则）

### 场景 2: 个人助理（跨天记忆）

**推荐**：分层记忆 + 向量数据库 + 摘要/压缩

- **滑动窗口**作工作记忆（当前对话上下文）
- **向量库**作长期记忆（历史对话、用户偏好、重要事实）
- **摘要压缩**定期归档（每 10 轮或 2000 tokens 触发一次总结）

### 场景 3: 低预算原型

**推荐**：滑动窗口 + 轻量摘要

- 先验证场景，再逐步引入向量库
- 滑动窗口保证基本对话连贯性
- 轻量摘要在关键节点触发（如用户说"记住这个"）

### 场景 4: 隐私优先场景

**推荐**：事实记忆 + 临时缓存

- 只保留必要的"事实记忆"（如用户偏好、关键设置）
- 对话内容用临时缓存，**会话结束后自动清理**
- 符合 GDPR"被遗忘权"要求

## 五、关键参数与监控指标

参数调不好，再好的策略也会翻车。

| 参数 | 建议起点 | 调整依据 |
|------|---------|---------|
| 滑动窗口大小 | 3-5 轮 | 根据对话复杂度调整 |
| RAG 召回数量（k 值） | 3-10 | 平衡相关性与上下文长度 |
| 摘要触发阈值 | 每 10 轮或 2000 tokens | 根据模型上下文窗口调整 |

**必须监控的 4 个指标**：

1. **命中率** — 检索到相关记忆的比例（目标 > 80%）
2. **事实准确率** — Agent 回答与事实的一致性（目标 > 90%）
3. **上下文压缩率** — 摘要/压缩后的 token 节省比例
4. **成本/轮次** — 每轮对话的 LLM 调用成本

## 六、避坑指南（血泪经验）

### ❌ 坑 1: 用全量记忆做长对话

**后果**：上下文窗口爆炸，LLM 响应变慢，成本飙升，且"中间信息遗忘"效应导致关键内容被忽略。

**解法**：超过 10 轮必须引入压缩或检索机制。

### ⚠️ 坑 2: 摘要策略缺少"事实核查"

**后果**：摘要过程中丢失关键细节（如数字、条件、例外），Agent 基于不完整记忆做出错误决策。

**解法**：摘要后追加事实核查步骤，或用"结构化摘要"（保留关键实体和关系，而非纯文本总结）。

### 🔧 坑 3: 向量库嵌入模型不更新

**后果**：语义漂移——新业务词汇在旧嵌入空间中找不到相近向量，召回率断崖式下跌。

**解法**：定期评估嵌入模型质量，业务词汇变化大时重新训练或切换模型。

### 📝 坑 4: 知识图谱没有维护流程

**后果**：知识过时、矛盾、孤岛——图谱越大，查询结果越不可信。

**解法**：建立**自动抽取 + 人工审核**的维护流程，定期巡检孤立节点和矛盾关系。

## 七、我们的实践：数字人 Agent 的记忆架构

在我们正在开发的 **AI Collab Hub** 数字人项目中，记忆系统采用了**分层架构**：

```
┌─────────────────────────────────────────┐
│          会话层 (Session Memory)         │  ← 滑动窗口 (5 轮)
│          内存级 Map，进程重启即失          │
├─────────────────────────────────────────┤
│          事实层 (Fact Memory)            │  ← SQLite FTS5
│          用户偏好、关键事件、长期设置       │
├─────────────────────────────────────────┤
│          语义层 (Semantic Memory)        │  ← 向量数据库 (未来)
│          对话历史向量化，支持语义检索       │
├─────────────────────────────────────────┤
│          本体层 (Ontology)               │  ← 知识图谱 (GOKES)
│          游戏业务实体关系，支持复杂推理     │
└─────────────────────────────────────────┘
```

**设计原则**：
- 先通路再提速：先用 SQLite FTS5 跑通事实记忆，再渐进引入向量库
- 明确分层边界：每层有清晰的职责和生命周期
- 可观测：命中率、响应时间、成本都有监控

## 结语

AI Agent 的记忆不是"越多越好"，而是**"该记的记准，该忘的忘掉"**。

选型时记住三点：
1. **从场景出发**，而不是从技术出发
2. **组合优于单一**，没有银弹
3. **监控驱动迭代**，用数据说话
